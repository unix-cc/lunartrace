# 周期预测规范 / 高频陷阱清单

> 用法：改 `domain/prediction/` 或任何展示预测的界面之前，通读本文件（很短）。
> 本文只管**预测口径与算法不变量**。决策背景见 `docs/adr/0003`；术语见 `CONTEXT.md`；日期语义见 `local-data-model.md`。
> 全部日期为**本地时区的自然日**（`LocalDate`），"今天"由 `Today` 注入。

## 1. 算法不变量（最高频 —— 务必先看）

- ✅ 预测是**纯函数**：输入（经期日集合、今天）相同 → 输出必然相同。不读系统时钟、不读数据库、不做 IO。
  - ❌ 在预测内部调 `LocalDate.now()` → 测试不可复现，"今天"出现两个来源。
- ✅ 统计与预测**只使用 `date ≤ 今天` 的经期日**；未来日期可以标记（用户提前记），但不参与计算。
  - ❌ 把未来标记算进周期长度 → 得到一个负数或 0 天周期。
- ✅ 无有效样本时不预测：`confidence = NONE` 且 `nextPeriodStart = null`、`fertileWindow = null`。
  - ❌ 无数据时回退到"默认 28 天" → 这正是 ADR-0003 拒绝的"固定 28 天"失败模式。

## 2. 口径（唯一来源，改这里等于改产品语义）

| 量 | 口径 |
|---|---|
| 经期段 | 连续经期日合并为一段；**允许 1 天间隔容错**（记为第 1、3 天 → 同段） |
| 周期长度 | 相邻两段**起始日**之差（天） |
| 有效样本 | 周期长度 ∈ `[15, 60]`；区间外不参与预计，仅计数 `excludedCount` |
| 预测依据 | 有效样本 ≥1 → 用最近 6 个的均值（`PredictionBasis.RECORDS`）；否则若用户填写了缺省周期长度且通过范围校验 → 用它（`USER_DEFAULT`）；都不满足 → 不预测（`NONE`） |
| 预测基准长度 | 由"预测依据"决定；`USER_DEFAULT` 时取用户填写的值（ADR-0005） |
| 缺省值范围校验 | 周期长度 `[15, 60]`、经期长度 `[3, 10]`——与有效样本区间**完全一致**；越界视为**未填写**（不夹取，夹取等于假装用户填的是别的数） |
| 缺省值的锚点 | 使用缺省值仍需要 ≥1 段经期作为起点；**零记录时填了也不预测** |
| 缺省值的置信度 | 一律 `LOW`，因此不显示排卵日、易孕窗口与阶段 |
| 统计量的来源 | `averageCycleLength / medianCycleLength / recentCycleLengths` **只由实测样本产生**，缺省值永不进入 |
| 下次经期起点 | 最后一段起始日 + 基准长度；若 ≤ 今天则反复 + 基准长度，**迭代上限 24 次**，超限则不预测 |
| 平均经期长度 | 最近 6 段的经期长度均值，四舍五入，缺省 5，夹取到 `[3, 10]` |
| 预测经期区间 | 起点 .. 起点 + (平均经期长度 − 1) |
| 预测经期长度 | 依据为 `RECORDS` 时 → 最近 6 段实测均值；依据为 `USER_DEFAULT` 时 → 用户填写的经期长度，未填则用缺省 5 天（**兜底状态刻意不用实测**，否则"还没记完"的一段会把区间压到 3 天）；最后统一夹取到 `[3, 10]` |
| 排卵日 / 易孕窗口 | 排卵日 = 起点 − 14；窗口 = 排卵日 − 5 .. 排卵日 + 1 |
| 置信度 | 有效样本 0 → `NONE`；1，或 ≥2 且极差 > 7 → `LOW`；2–3 且极差 ≤ 7 → `MEDIUM`；≥4 且极差 ≤ 4 → `HIGH` |
| 易孕信息展示条件 | **仅 `confidence ≥ MEDIUM`**；`NONE`/`LOW` 时 `ovulationDay` 与 `fertileWindow` **必须同时为 `null`**（只藏窗口、漏出排卵日等于换个说法继续误导） |
| 顺推超限 | 顺推超过 24 次仍追不上"今天" → 日期字段全部为 `null`，但**保留真实置信度**（样本本身有效） |

## 3. 周期阶段与排卵信息（口径详见 ADR-0004）

| 量 | 口径 |
|---|---|
| 当前周期 | 最后一段经期段的起始日 → 下次经期起点 − 1 天（下次起点由顺推保证晚于今天） |
| 周期第 N 天 | `今天 − 最后一段起始日 + 1`。**事实**：只要有经期记录就有值，不受置信度影响 |
| 排卵日预计 | `下次经期起点 − 14`；仅 `confidence ≥ MEDIUM` 时存在 |
| 阶段判定 | 今天 ≤ 最后一段结束日 → `MENSTRUATION`（实测）；否则看排卵日：< 排卵日−1 → `FOLLICULAR`；排卵日±1 → `OVULATION`；> 排卵日+1 → `LUTEAL`；无排卵日 → `UNKNOWN` |

- ✅ **只展示"排卵日预计"这个单日**，不把"排卵期"作为区间展示。
  - ❌ 同时展示"排卵期（3 天）"与"易孕窗口（7 天）"两个区间 → 天数与含义都不同，用户无法判断该信哪个。
- ✅ 阶段与排卵日的门槛一致（≥ MEDIUM）；"周期第 N 天"单独按"事实"处理，不受门槛限制。
  - ❌ 把两者一刀切 gate 在 MEDIUM 上 → 只记录过一次经期的用户连"周期第几天"都看不到。
- ✅ `UNKNOWN` 必须在 UI 上有文字说明（例如"再记录 N 次经期开始就会显示"）。
  - ❌ 留白 → 用户读成"功能坏了"。
- ✅ 禁止评价性表述：不得出现"已推迟 N 天""周期异常""是否排卵""安全期""是否怀孕"。周期第 N 天超过基准长度时照实显示。
- ✅ 排卵信息不得用于避孕/备孕决策，文案保持"预计"。

## 4. 边界情况（每条都必须在单元测试里出现）

- ✅ 无任何经期日 → `NONE`，全部预测字段 `null`。
- ✅ 只有 1 段经期（0 个周期长度） → `NONE`，不预测。
- ✅ 只有 1 个有效周期长度 → 基准长度 = 该长度，`LOW`。
- ✅ 最后一段起始日 + 基准长度已经过去（用户几周没打开应用） → 顺推到**未来最近**的一个起点，绝不返回过去的日期。
- ✅ 顺推迭代超过 24 次（长期未记录） → 不预测（`NONE`），而不是给出一个荒谬的远期日期。
- ✅ 所有周期长度都落在 `[15,60]` 之外（例如极端不规律） → 有效样本 0 → `NONE`，且 `excludedCount > 0` 需如实展示。
- ✅ 经期段跨月（1 月 29 日 ~ 2 月 3 日）、跨年（12 月 30 日 ~ 1 月 2 日） → 用 `LocalDate.plusDays` 计算，天数正确。
- ✅ 1 天间隔容错生效（记为 3 月 1、3 日 → 1 段，不是 2 段）。
- ✅ 2 天以上间隔不合并（记为 3 月 1、4 日 → 2 段），且产生一个 3 天的"周期长度"（会被 `[15,60]` 过滤掉）。

## 5. 禁止事项

- ❌ 输出任何医学结论（是否怀孕、是否异常、是否排卵期已到、建议就医）→ 见 `PRODUCT.md` §3。
- ❌ 把预测值画得与实测值视觉相同（必须虚线/低透明度区分）。
- ❌ 在置信度 `LOW`/`NONE` 时展示易孕窗口或"距下次经期还有 X 天"的具体数字 → 误导。
- ❌ 因为 `excludedCount > 0` 就在界面上暗示用户身体有问题；只做中性说明。
- ❌ 把"基准长度"用于历史解读（历史周期长度永远显示实测值，不显示基准长度）。

## 提交前快速自检

- [ ] 预测函数仍是纯函数（无时间、无 IO、无 Android 依赖）
- [ ] 用户填写的缺省值没有进入任何统计量（统计页显示的数字必须来自实测）
- [ ] 缺省值的范围校验与有效样本区间一致，且越界时是"视为未填写"而不是夹取
- [ ] 有实测样本时，缺省值被忽略（实测优先，且 UI 不再声称依据是用户填的）
- [ ] 排卵信息仍以**单日**呈现，没有引入第二个区间（"排卵期 X–Y"）
- [ ] `cycleDay`（事实）与 `phase`（推算）的门槛差异没有被"顺手统一"成同一个置信度条件
- [ ] `UNKNOWN` 在 UI 上有文字说明，不是留白
- [ ] 没有出现评价性文案（已推迟 / 异常 / 是否排卵 / 安全期）
- [ ] 未来日期的记录没有进入统计
- [ ] `NONE`/`LOW` 时 `nextPeriodStart`/`fertileWindow` 的 `null` 语义在 UI 上被正确处理
- [ ] 顺推方向永远是"向未来"，且 24 次上限仍在
- [ ] 上述每条边界情况都有对应单元测试，且 `python scripts/check-coverage.py` 通过（该模块 ≥85%）
