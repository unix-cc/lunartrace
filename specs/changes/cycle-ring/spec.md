# 周期环（第 N 天 + 阶段 + 经期/排卵标记）

Status: done

> **后续变更**：环原本放在日历页顶部，真机核对后认为该位置不对，已迁到独立的**主页**标签页。
> 见 `specs/changes/home-tab/spec.md`（本文件描述的环本身的行为未变）。

## Problem Statement

日历页现在只回答"这个月哪些天是经期"，而用户打开应用最想知道的是**"我现在处在周期的什么位置"**。
这件事目前退化成了预测卡里的一行小字：

> 今天处于黄体期 · 周期第 24 天

三个问题：

1. 它是纯文字的，扫一眼看不出"这一圈走到哪了"；
2. 它和"下次经期预计"混在同一张卡里，主次不分；
3. 环上本该有的信息（本次经期是哪几天、排卵日落在哪一格）被摊平到整个月历上，
   用户得自己在 42 个格子里找。

## Solution

在日历页顶部加一个**周期环**：

- 环按"本周期"等分（起点 = 本次经期的开始日，格数 = 预测使用的基准长度）；
- 已走过的部分用主色弧表示，**实测经期日**与**排卵日**在环上有各自的标记；
- 圆心显示：大号"第 N 天"、阶段名（如"黄体期"）、今天日期与星期；
- 没有预测时不画刻度，圆心显示"还没有记录"，不再假装有一圈进度。

同时把预测卡里那行"今天处于… · 周期第 N 天"**删掉**（信息移进环里，避免两处重复）。

## User Stories

1. 作为使用者，我希望打开应用第一眼就看到"我在这个周期的哪个位置"，而不是读一行字。
2. 作为使用者，我想在环上看到这次经期是哪几格、排卵日大概在哪一格。
3. 作为使用者，如果应用还推不出预测，我希望环**不要**画出一圈假的进度，而是直说"还没有记录"。
4. 作为使用者，当我的周期已经超过预计长度（很久没记录），我希望看到"这一圈已经走完"而不是被截断成假象。

## Implementation Decisions

### 环覆盖的是"本周期"

- 起点 = 本次周期的开始日。由 `position.cycleDay` 反推：`cycleStart = 今天 − (cycleDay − 1)`
  —— 这与预测卡显示的天数是**同一个数**，不会出现"环说第 5 天、卡说第 1434 天"。
- 格数 = 预测实际使用的**基准长度**。因此 `CyclePrediction` 新增字段 `basisCycleLengthDays`
  （实测均值 或 用户填写的缺省值），这是**口径无关的补充信息**：预测行为完全不变，
  只是把"我这次用了多少天当基准"说出来，环与将来的文案都用得上。
- 标记的换算：`index = 日期 − 起点 + 1`，只保留落在 `1..格数` 内的。
  于是"很久没记录"时实测经期日仍然会落在前几格（起点就是那次经期的开始日），
  而超出的部分通过 `isOverdue` 表达。

### 不画什么

- **不画预测经期**：那是**下一个**周期的事，画在"本周期"的环上会误导（参考设计的环也只画本次经期）。
- 不画症状：格子太小，20 个症状挤在环上只会更乱，症状仍在日历与记录面板里。
- 无预测时不画刻度、不画进度弧：宁可不画，也不画一圈假进度。

### 代码

- `ui/calendar/CycleRingData.kt`（新）：纯函数 `CycleRingData.of(prediction, position, periodDates, today)`
  —— **本轮唯一可自动验证的逻辑**，先写失败测试。
- `ui/calendar/CycleRing.kt`（新）：Canvas 绘制（进度弧 + 标记点 + 圆心文字）。
  角度约定：**0 度在正上方，顺时针**；第 i 格的中心角 = `-90 + (i - 0.5) / 格数 × 360`。
- `domain/model/CycleModels.kt`：`CyclePrediction` 增加 `basisCycleLengthDays: Int?`。
- `domain/prediction/CyclePredictor.kt`：在两条依据路径（实测 / 用户缺省）上写入该字段。
- `ui/calendar/CalendarUiState.kt`：增加 `ring: CycleRingData`。
- `ui/calendar/CalendarScreen.kt`：环放在页面最顶部；删除预测卡里的 `CurrentPositionLine`。

## Testing Decisions

**接缝**：`CycleRingData.of`（纯函数，JVM 单测，CI 运行）。

**本轮流程**：先写测试并运行**确认它红**（桩实现返回空数据），再补实现。

必须覆盖的边界：

1. 没有预测（`basisCycleLengthDays == null`）→ 全部为空、不画刻度
2. 正常：基准 28、今天第 5 天 → 起点正确、实测经期日映射到第 1–3 格、排卵日映射到第 15 格
3. 超出基准（今天第 1434 天）→ `isOverdue == true`，且起点仍是那次经期的开始日（标记落在第 1 格）
4. 排卵日落在窗口之外 → `ovulationDayIndex == null`（不画到环上）
5. 没有排卵日（置信度不足）→ `ovulationDayIndex == null`
6. 没有周期天数（零记录）→ 全部为空

**明确不测**：Canvas 绘制本身（角度、颜色、线宽）——无设备、无截图测试，与既有决定一致。
角度约定写进代码注释，并在真机上由使用者核对。

## Out of Scope

- 新增"主页"底部导航页（本轮的环放在日历页顶部；若真机上看觉得位置不对，再决定是否独立成页）。
- 症状标记上环。
- 环的拖拽/点击交互（不可点，纯展示）。
- 动画过渡。

## Further Notes

- 这一轮的目标不是"画得和参考设计一样"，而是把**已经算出来的位置信息**变成一眼可读的形状。
  所有数字都来自既有预测与位置模型，没有引入任何新的口径。
- 位置放在日历页顶部意味着日历与记录面板会更靠下（需要滚动）。这是本轮最需要真机确认的取舍，
  若滚动代价过大，备选方案是把环独立成"主页"页。
