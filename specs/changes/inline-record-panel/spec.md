# 内联记录面板与点选即时保存

Status: done

## Problem Statement

记录区现在是一个**模态弹层**：点日期 → 弹层遮住日历 → 改完点"保存" → 弹层关闭。
参考设计不是这样：记录区就在日历下方，点选**立即生效**，没有保存按钮。

模态弹层的三个具体问题：

1. 弹层遮住了日历，而用户正是在对着日历决定"这一天对不对"；
2. "保存"是多余的一步——记录是低风险操作，没有需要"确认"的后果；
3. 弹层关闭后用户看不到"这一天到底记了什么"，只能再点开确认。

## Solution

1. 记录区改为**日历下方的内联面板**（预测卡 → 月份切换 → 网格 → 图例 → **记录面板**），
   点某一天即切换面板内容，**每个控件立即生效**（无保存按钮）。
2. 面板内容与弹层一致：日期标题（含星期）、经期流量水滴、症状、心情、备注、"清空这一天"。
3. 网格上**高亮选中的那一天**（数字外一圈中性描边，与"今天"的加粗主色并存）。
4. 「记录今天」保留，语义变成"把选中日切回今天"。

## User Stories

1. 作为使用者，我希望点一下水滴就完成记录，而不是点完还要找"保存"。
2. 作为使用者，我希望在改记录时仍然看得见日历（今天是这个月的第几格、上一次经期在哪）。
3. 作为使用者，我希望一眼看出面板里编辑的是哪一天（日历上有明确的选中标记）。
4. 作为使用者，当我在同一天连点几次（改流量、勾症状、取消再勾回）时，我希望最终存下来的就是我最后看到的样子。
5. 作为使用者，我希望备注打得慢也不会因为一次误触而丢失（不需要一路点保存）。

## Implementation Decisions

### 交互

- **即时保存**：流量、取消经期标记、症状、心情——每次操作立刻入队写库。
- **备注**：600ms 防抖后写库；**切换日期或"清空这一天"时先把待写的备注强制落库**。
  - 诚实标注残余风险：若在防抖窗口内进程被杀，最后几百毫秒的输入会丢失（备注是低价值数据，可接受；
    换来的是"不需要保存按钮"）。
- **选中日高亮**：数字外加一圈 1dp 的中性描边（28dp 圆），不与既有的易孕底色、胶囊条、
  排卵点、症状点、今天加粗冲突。

### 为什么需要一个"覆盖层"（关键决策）

UI 显示值**不能**直接读已持久化的数据，原因是：**持久化是异步的**。
连点两次症状，第二次会读到尚未更新的旧集合，于是第一次的点选被覆盖（丢写）。
所以引入 `localEdits`（就是现有的 `DayDraft` 类型）作为**当前选中日的本地覆盖层**：

- 显示值 = `localEdits ?: 由已存数据构造`（`DayRecordEditing.fromStored`）；
- 每次操作**同步**更新覆盖层（UI 立刻正确），再把整行的完整快照**入队写库**；
- 切换日期时清空覆盖层（此前先 flush 备注）——回到该日时显示值重新由已存数据构造。

### 写库必须串行化

快速连点会并发发起多个写操作，理论上可能在数据库层乱序，导致"最后看到的不是最后存下的"。
因此所有写操作进入**单一队列**（`Channel.UNLIMITED` + 单消费者协程），按入队顺序依次执行。

两个具体的取舍：

- **必须是无限缓冲、不能是 conflated**。conflated 只保留最新一条，用户在**两个不同日期**上快速操作时
  会丢掉其中一天——那是数据丢失，不是"合并成最终状态"。
- 不选"整体防抖"是因为那会丢掉中间的意图（例如勾上又取消），而队列能保证**最终状态 = 最后意图**。

### 代码

- `ui/calendar/DayRecordEditing.kt`（新）：纯函数——`fromStored` / `setFlow` / `toggleSymptom` /
  `toggleMood` / `withNote`。这是本轮**唯一可自动验证的逻辑**，因此先写失败测试。
- `ui/calendar/DayRecordPanel.kt`（新）：内联面板，替换 `DayRecordSheet.kt`（模态弹层删除）。
- `ui/calendar/DayRecordActions.kt`：去掉 `onSave` / `onDismiss`。
- `ui/calendar/CalendarUiState.kt`：`selected: DayDraft?`（弹层是否打开）改为
  `selectedDate: LocalDate` + `record: DayDraft`（非空，面板总是显示）。
- `ui/calendar/CalendarViewModel.kt`：`selectedDate` + `localEdits` + 写队列 + 备注防抖。
- `ui/calendar/CalendarScreen.kt`：弹层换成内联面板；`showLastPeriodPicker` 不变
  （"记录上次经期开始"仍用日期选择器，选完直接切到该日）。
- `ui/calendar/MonthGrid.kt`：增加 `selectedDate` 参数与选中环。

## Testing Decisions

**接缝**：`DayRecordEditing` 的五个纯函数（JVM 单测，CI 运行）。

**本轮流程**：先写测试并运行**确认它红**（桩实现故意不实现覆盖层合并），再补实现。

必须覆盖的边界：

1. 无条目时 `fromStored` → 流量来自传入值，症状为空集、心情为 null、备注为空串
2. 有条目时 `fromStored` → 四个字段全部来自条目
3. `toggleSymptom` 能加也能减，且**不动**心情与备注
4. `setFlow(null)`（取消经期标记）**保留**症状 / 心情 / 备注——不能顺手清掉用户已记的内容
5. `toggleMood` 再点一次取消，且不动其他字段
6. `withNote` 超过 500 字截断（复用 `SymptomEntry.MAX_NOTE_LENGTH`）

**明确不测**：防抖与写队列的时序（需要协程测试基建与注入时钟，本仓库暂不引入 `kotlinx-coroutines-test`；
这两个机制的正确性靠"单一队列 + 完整快照"的结构保证，而不是靠测试）。

## Out of Scope

- 「经期结束」显式开关（要改 Room schema → Grill）。
- 「爱爱」记录（已确认不做）。
- 把面板做成可折叠/可拖动（参考设计也不需要）。
- 皮肤/动画过渡。

## Further Notes

- 这一步会**删掉模态弹层**：`DayRecordSheet.kt` 被 `DayRecordPanel.kt` 取代。
  回滚方式是把该文件恢复并还原 `CalendarScreen` 的面板调用——因为改动集中，回滚成本可接受。
- 参考设计的记录区还含「经期结束」开关与「爱爱」开关：前者要改 schema，后者已明确不做。
