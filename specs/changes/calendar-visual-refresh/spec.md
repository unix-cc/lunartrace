# 日历视觉对标（胶囊标记 / 四项图例 / 粉红配色）

Status: done

## Problem Statement

当前日历用"圆形底 + 描边"表达标记，四个图例项里还有一项是"有症状记录"。
用户拿来同类应用（小月记）的截图对照后提出的差距很具体：

- 经期日与预测经期日看不出"连续成段"，而是一堆孤立的圆点；
- 图例里没有"排卵日"这一项——上一轮刚把排卵日算出来，却在日历上找不到它；
- 顶部是 Material 默认的 TopAppBar，没有任何产品气质；
- 一周从周一开始，与参考设计（周日）不一致。

## Solution

只改**呈现**，不改任何口径、不碰 schema、不碰隐私路径：

1. 一周起始改为**周日**。
2. 经期日 → **实心胶囊横条**；预测经期日 → **空心胶囊横条**；连续多天时只在外侧两端倒圆角，
   视觉上连成一条带（这正是参考设计看起来"成段"的原因）。
3. 易孕窗口 → 格子浅黄底；排卵日 → 格子底部居中的橙色小点；有症状记录 → 右上角灰色小点。
4. 图例改为四项，与参考设计一致：经期 / 预测经期 / 易孕期 / 排卵日。
5. 顶部改为粉红渐变头（白字白图标），主色向参考设计的玫红靠拢。

## User Stories

1. 作为使用者，我想一眼看出"这次经期是从哪天到哪天"——连续的日子应当连成一条带，而不是一堆孤立的点。
2. 作为使用者，我想在同一张日历上区分"已经发生的经期"与"预计会来的经期"（实心 vs 空心）。
3. 作为使用者，我想看到排卵日具体落在哪一格（上一轮算出它之后，日历上却找不到）。
4. 作为使用者，我想知道哪些天在易孕窗口内（浅黄底）。
5. 作为使用者，我希望一周从周日开始，与我熟悉的日历一致。
6. 作为使用者，当数据不足以推算排卵时，我希望那几格**什么都不显示**，而不是画一个不确定的标记。

## Implementation Decisions

- **网格布局抽成纯函数**：`ui/calendar/MonthGridLayout.kt`（`monthGrid(month)`、`ribbonEdges(dates, date)`），
  从 `CalendarViewModel` 的私有方法里搬出来，让它可以在 JVM 上被单元测试。
  现有实现把这段逻辑藏在 ViewModel 私有函数里，属于"逻辑不可测"——本次一并修正。
- **胶囊形状**：按 `ribbonEdges` 决定四个角的圆角半径（左端倒左圆角、右端倒右圆角、中间不倒），
  形状由 `RoundedCornerShape` 的四个角分别指定，不引入新依赖。
- **标记优先级**（同一格可能同时命中多项）：实心胶囊（经期）> 空心胶囊（预测经期）> 浅黄底（易孕窗口）；
  排卵日小点与症状小点独立叠加，位置分开（底中 vs 右上）以免互相遮挡。
- **`DayMarks` 增加 `ovulation` 字段**；排卵日来源是 `CyclePrediction.ovulationDay`（单日），
  因此它天然只在 `confidence ≥ MEDIUM` 时存在——**低置信度时日历上不会出现任何排卵/易孕标记**，
  这与 ADR-0004 §3 一致，也是与参考设计刻意不同的一点（参考设计看起来是永远显示）。
- **配色**：`ui/theme/Theme.kt` 的 primary/primaryContainer 向玫红调整，新增头部渐变用的两个颜色常量。
  深色主题同步调整，不新增颜色资源文件。
- **图例移除"有症状记录"**：它退化为格子右上角的小点（不在图例里占位），图例只保留四项核心语义。

## Testing Decisions

**接缝**：`MonthGridLayout`（纯函数，JVM 单测，CI 运行）。这是本轮唯一有"逻辑"的部分——
网格起始对齐与"胶囊两端"的判定都容易算错（off-by-one 与边界月份），值得测。

**本轮流程**：先写 `MonthGridLayoutTest` 并运行**确认它红**（当前实现是周一起始、且没有连段判定），
再补实现转绿。与上一轮一致，红先绿后必须留输出证据。

必须覆盖的边界：

1. 某月 1 日恰好是周日 → 首格就是 1 日，无前置补齐
2. 某月 1 日是周一 → 首格是上月最后一天（周日）
3. 网格恒为 42 格，末格覆盖到下月中旬
4. 跨年（12 月 → 次年 1 月）
5. 连段判定：连续三天中，中间一天两端都不倒角；单日两端都倒角；一段的起止日各倒一端

**明确不测**：绘制本身（颜色、圆角半径、渐变方向）——无设备、无截图测试，与既有决定一致。

## Out of Scope

- **「爱爱」记录**：**已由使用者确认不做**（2026-10-10）。原因不是隐私，而是产品定位：它会直接导向
  备孕/避孕用途，而备孕指导需要医学背书。已写入 `PRODUCT.md` §3 反例表，不是"待定"。
- **「备孕中」状态开关**：同源，一并明确不做（已写入 `PRODUCT.md` §3）
- **让用户自定义缺省周期长度/经期长度**（参考设计图 2 的"周期长度 45 天"）：
  这改的是预测口径（现在是"无有效样本就不预测"），价值很高但必须走 Grill
- **底部记录面板改成行式布局**、**主页环形可视化**、**「我」页**、**提醒通知**：留待后续切片
- 统计页图表美化（加数据点标签与日期轴）

## Further Notes

- 参考设计有"主页"环形图（第 N 天 + 经期结束日期 + 下一次经期弧）。它依赖的阶段与周期天数我们已经有了，
  只差绘制；但它涉及大量视觉细节，在没有真机反馈前不宜一次做完。
- 本轮改动无法在本机核对视觉效果（无设备），因此**必须由使用者装包后给截图反馈**，
  这也是把它切成"每片可看"的小步的原因。
