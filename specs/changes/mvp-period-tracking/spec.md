# MVP：离线经期与症状记录

Status: done

## Problem Statement

想记录月经、症状和心情的人，目前只能在两类工具里选：
一类要求注册账号并把记录同步到云端（隐私代价不透明，且必须有网络）；
另一类功能堆到难以忍受（社区、商城、内容推送）。

而"记录"这件事本身只需要三样东西：点一下就能记、能看懂日历、能对下一次有个大致预计。
在拿到手机、没有网络、不想登录的前提下，这三件事都没有干净的解决方案。

## Solution

一个**零网络、纯本地**的 Android 记录本：

- 月历上点任意一天即可标记经期、流量、症状、心情与备注；
- 日历用可区分的样式展示"实测经期 / 预计经期 / 易孕窗口"；
- 统计页给出平均与中位周期长度、平均经期长度、最近周期长度趋势、症状频次；
- 可选的应用锁（PIN）保护记录内容；
- 一键清除全部数据，真删除。

应用不声明任何联网权限，记录不参与系统云备份，也不存在账号体系。

## User Stories

1. 作为使用者，我想在月历上点一个日期就标出经期并选流量，这样我不必先读完说明才能记录。
2. 作为使用者，我想在记录经期时顺便勾选症状与心情，这样"这天怎么难受"能和日期一起留下。
3. 作为使用者，我想一眼分辨日历上哪些是实测、哪些是预计，这样我不会把预计当成事实。
4. 作为使用者，我想在记录足够多之后看到"下次经期预计在 X 日（数据较充足）"，这样我能提前安排事情。
5. 作为使用者，当我的周期波动很大时，我希望应用**不要**给出易孕窗口，这样我不会被不可靠的推算误导。
6. 作为使用者，当我的记录里出现明显偏短的间隔时，我希望应用不要悄悄把它算进平均，也不要暗示我身体有问题。
7. 作为使用者，当我在没有网络的地方打开应用时，我希望所有功能都能正常使用。
8. 作为使用者，我想给应用加一个 PIN，这样别人拿到我的手机不会直接看到记录内容。
9. 作为使用者，我想一次性清空全部记录与 PIN 设置，并且知道这个操作不可恢复。
10. 作为使用者，我想在"过了一个月没打开应用"之后，看到的下次经期预计仍然在**未来**，而不是已经过去的日期。

## Implementation Decisions

- **平台**：Kotlin 2.0 + Jetpack Compose（Material 3），单模块 `:app`，`minSdk 26`（直接用 `java.time`，免 desugaring）。
- **分层**：`ui → domain ← data`；`domain` 不依赖任何 `android.*`，因此预测逻辑可在 JVM 单测里验证。
- **持久化**：Room（`period_days`、`symptom_entries`），日期以 `epochDay` 长整型存储，经 `Converters` 与 `LocalDate` 互转；`exportSchema = true` 且 schema JSON 入库。设置与 PIN 元数据用 DataStore Preferences。
- **日期语义**：所有"哪一天"都是 `LocalDate`；"今天"由 `core/time/Today` 注入，禁止直接调用 `LocalDate.now()`。
- **预测**：`domain/prediction` 中的纯函数，口径以 `specs/capabilities/cycle-prediction.md` 为准（最近 6 个有效样本均值、有效区间 15–60 天、置信度四档、易孕窗口仅 ≥MEDIUM 展示、顺推上限 24 次）。决策背景见 `docs/adr/0003`。
- **依赖注入**：手动 `AppContainer`，不引入 Hilt（注入点 <10 个）。
- **隐私**：清单不声明任何权限；`allowBackup="false"`；应用锁开启时窗口加 `FLAG_SECURE`；PIN 用 PBKDF2-HMAC-SHA256（≥120000 次迭代，随机 salt，常量时间比较），忘记 PIN 只能清除数据；生产代码完全不使用日志 API。
- **统计口径**：症状频次 = 全部症状条目中出现的次数，降序取 Top 5，同次数按枚举声明顺序。
- **文案**：UI 文案集中在 `ui/common/Labels.kt`（P0 只做中文；将来 i18n 时替换为字符串资源，因此不散落在组件里）。预测必须带"预计"，禁止"准确率/概率/诊断"。
- **新增依赖理由**：Compose（重复视图成本最低）、Room（Flow 自动刷新）、DataStore（键值 + Flow）、detekt 与 detekt-formatting（L1 门禁的唯一可自动判定来源）、JUnit4（JVM 单测）。明确不引入 Retrofit/图表库/上报 SDK/Robolectric/Hilt。

## Testing Decisions

**接缝（已约定，不在未约定接缝上写测试）**

| 接缝 | 层级 | 测什么 |
|---|---|---|
| `CyclePredictor.analyze` / `CycleMath` | JVM 单测（`testDebugUnitTest`，CI 运行） | 分段与容错、异常样本排除、置信度分档、跨月跨年、未来日期忽略、顺推与上限、区间夹取 |
| `PinHasher.create/verify`、`PinPolicy.isValid` | JVM 单测（CI 运行） | 正确/错误 PIN、salt 随机性、派生确定性、迭代次数下限、PIN 形态 |
| `EnumCodec` | JVM 单测（CI 运行） | 未知枚举名降级而不崩溃、集合编码顺序稳定 |

**什么算好测试**：只测外部可观察行为（给定记录 → 给定预测），期望值来自 `cycle-prediction.md` 的手算样例，绝不用实现里的同一算式重算期望值。
**明确不做的测试**（并说明理由，避免"写了不跑的测试是负债"）：
- Room DAO：保持"一行查询/一行写"的薄度，无业务逻辑；本机无设备，instrumented 测试无法进入 CI。
- Compose UI：无设备/模拟器，不做 instrumented 或截图测试；UI 正确性靠编译 + 口径表人工核对（如实标注为未覆盖）。
**同类先例**：本仓库第一个 change，无先例可循。

## Out of Scope

- 提醒通知（WorkManager）、体温曲线、CSV/文件导出、备份恢复、多语言、桌面小部件。
- 账号、云同步、任何联网能力、任何分析与崩溃上报。
- 医学结论（是否怀孕/周期是否异常/是否排卵）、避孕或备孕建议。
