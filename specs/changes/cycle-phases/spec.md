# 周期阶段与排卵期呈现

Status: done

## Problem Statement

现在的应用只回答了两个问题："这次经期是哪几天"和"下次经期预计哪天"。
但用户对周期的理解是按阶段走的：经期结束后进入**卵泡期**，中间有**排卵期**，之后是**黄体期**，然后下一次经期。

当前版本把这些信息全都藏了起来：
- 日历上只有一片"易孕窗口"的底色，用户看不出排卵日在哪一天，也不知道自己现在处于哪个阶段；
- 没有"今天是本次周期第几天"这种最基本的定位；
- 记录满两次经期之前，界面只说"还没有足够的记录"，用户不知道还差多少、也看不到任何进展。

结果：核心能力（记录月经 → 推测下一次 → 中间的排卵期）里，"中间的排卵期"实际上是**不可见**的。

## Solution

在**不新增任何数据输入**的前提下，把既有预测结果展开成用户能看懂的周期阶段：

1. 记录月经 → 推测下次经期（既有能力，不变）。
2. 由"下次经期起点 − 14 天"推出**排卵日预计**，并据此把当前周期切成四个阶段：
   经期期 / 卵泡期 / 排卵期 / 黄体期。
3. 首页预测卡直接展示：
   - 下次经期预计日期（既有）
   - **排卵日预计**（新增，单日）
   - 易孕窗口预计区间（既有，仅数据充足时）
   - **当前阶段 + 本次周期第几天**（新增）
4. 数据不足时如实降级：只有经期记录时只显示"周期第 N 天"（这是事实），不显示任何阶段与排卵日预计（那是推算）。

明确不做医学判断：不判断是否排卵、不判断是否怀孕、不使用"安全期"这类暗示可避孕的说法。

## User Stories

1. 作为使用者，我记录过一次经期后，就希望能看到"今天是本次周期第 3 天"——这是我自己的事实，不需要它做任何推算。
2. 作为使用者，当我的记录足够（≥2 个有效周期长度）时，我想看到"排卵日预计 4 月 9 日"，这样我知道周期中间大概哪一天。
3. 作为使用者，我想看到"当前：黄体期 · 周期第 24 天"，这样我能把身体感受和周期位置对上。
4. 作为使用者，当我的数据还不足时，我希望应用**不要**编出一个阶段或排卵日，而是告诉我"再记录几次经期开始就会显示"。
5. 作为使用者，当我的周期波动很大（极差 > 7 天）时，我希望排卵信息**不显示**，因为那时的推算不可靠。
6. 作为使用者，我不想看到"你的经期已经推迟 5 天"这类评价性文案——只给我事实与预计。

## Implementation Decisions

### 口径（唯一来源将同步到 `specs/capabilities/cycle-prediction.md`）

- **当前周期**：从最后一段经期段的起始日算起，到"下次经期起点 − 1 天"为止（下次经期起点由既有口径顺推得到，永远晚于今天）。
- **周期第 N 天**：`今天 − 最后一段起始日 + 1`。**只要有经期记录就有值**（纯事实，不含推算），与置信度无关。
- **排卵日预计**：`下次经期起点 − 14`（沿用既有黄体期 14 天假设），**仅在 `confidence ≥ MEDIUM` 时存在**（这是既有规则，不变）。
- **阶段划分（按今天所处位置）**：
  | 条件 | 阶段 |
  |---|---|
  | 无经期记录 | `UNKNOWN` |
  | 今天 ≤ 最后一段经期段的结束日 | `MENSTRUATION`（实测，不是推算） |
  | 有排卵日且 今天 < 排卵日 − 1 | `FOLLICULAR` |
  | 有排卵日且 排卵日 − 1 ≤ 今天 ≤ 排卵日 + 1 | `OVULATION` |
  | 有排卵日且 今天 > 排卵日 + 1 | `LUTEAL` |
  | 其余（有记录但无排卵日，即置信度不足） | `UNKNOWN` |
- **排卵期 ≠ 易孕窗口**：排卵期是 3 天展示窗口（排卵日 ±1），易孕窗口是 7 天（排卵日 −5 .. +1，沿用既有口径）。
  两者并存时 UI 必须能区分：预测卡里写"**排卵日预计**"这个单日，不写"排卵期 X–Y"，避免出现两个互相打架的区间。
- **禁止**：评价性文案（"已推迟 N 天""周期异常""是否排卵""安全期"）。周期第 N 天超过基准长度时照实显示，不做任何评价。

### 代码

- `domain/model/CyclePhase.kt`：`enum CyclePhase { MENSTRUATION, FOLLICULAR, OVULATION, LUTEAL, UNKNOWN }` 与 `data class CyclePosition(cycleDay: Int?, phase: CyclePhase)`。
- `CycleInsight` 增加 `position: CyclePosition`；阶段在 `CyclePredictor` 内由既有的 episodes + prediction 推导，**不引入任何新的时间源或数据源**，仍然是纯函数。
- `ui/common/Labels.kt` 增加阶段文案；预测卡增加两行（排卵日预计 / 当前阶段与周期第几天），并在数据不足时给出"再记录几次就会显示"的说明。
- 日历本轮的视觉**不变**（不新增第四种格子标记）：理由见 `docs/reviews/0003-plan-review-cycle-phases.md` 第 2 条——本轮无法在真机上核对视觉，先不引入难以验证的样式改动。

### 明确不做（本轮）

- 不做基础体温、不做提醒通知、不做导出。
- 不改预测算法本身：基准长度仍是最近 6 个有效样本的**均值**。改成中位数或加权需要证据（回测数据），没有证据就不改——"智能"体现在把推算讲清楚，而不是换一个没人验证过的公式。

## Testing Decisions

**接缝**：`CyclePredictor.analyze` 返回的 `position` 字段，JVM 单元测试（`testDebugUnitTest`，CI 运行）。它是纯函数，可固定"今天"。

**本轮流程承诺（偿还自评表里的那个 0）**：先写失败测试并**运行一次确认它红**，再写最小实现，最后跑绿。
`docs/reviews/0002-code-review-mvp.md` 已记录上一轮"红先绿后"未执行，本轮必须补上，并在收口记录里给出两次运行的实际输出。

**必须覆盖的边界**（每条一个用例）：

1. 无任何记录 → `cycleDay == null`、`phase == UNKNOWN`
2. 只有 1 段经期（0 个周期长度）→ 有 `cycleDay`（事实），`phase == UNKNOWN`（不推算）
3. 今天仍在最后一段经期内 → `MENSTRUATION`
4. 今天在经期结束后、排卵日前 2 天以上 → `FOLLICULAR`
5. 今天落在排卵日 ±1 → `OVULATION`
6. 今天在排卵日 +1 之后 → `LUTEAL`
7. 波动过大（置信度 LOW，无排卵日）→ `phase == UNKNOWN`，但 `cycleDay` 仍有值
8. 顺推超限（长期未记录，无下次经期）→ `cycleDay` 照实很大，`phase == UNKNOWN`
9. 跨月/跨年的周期 → `cycleDay` 与阶段边界正确

**明确不测**：Compose 界面（无设备，与既有决定一致）。

## Out of Scope

- 基础体温、体温曲线
- 提醒通知
- 导出 / 恢复
- 日历新增阶段色带（等能在真机上看效果再决定）
- 算法升级（中位数 / 加权 / ML）
- 预测回测展示（"上次预计偏晚 2 天"）—— 见 Further Notes，作为下一个候选

## Further Notes

- **下一步候选（未定）**：预测回测展示。用历史数据做"只用当时已有的记录"的滚动预测，算出平均偏差、命中率，展示"你的预计平均偏早 1.2 天"。
