# 记录弹层改为行式布局与水滴流量选择

Status: done

## Problem Statement

参考设计（小月记）的记录区是**行式**的：一行"经期结束"配一个开关、一行"流量"配一排可点的水滴、
日期标题自带星期。而我们的记录弹层是 **chip 堆**：

- 流量是 4 个文字 chip（点滴/少/中/多），选中状态靠底色，一眼看不出"程度"；
- 症状 10 个 chip、心情 6 个 chip 全部平等铺开，没有任何分组层级；
- 日期标题只有"2026年10月10日"，没有星期——用户要自己算今天是周几。

结果：这个弹层能用，但**没有层级**。用户每次都要在 20 个 chip 里找自己要的那一个。

## Solution

只改这一个弹层的呈现与流量选择方式，不动数据、不动口径：

1. 日期标题加上星期（如"2026年10月10日 周六"）。
2. 每个区块改成**标签行 + 内容**的统一结构（经期流量 / 症状 / 心情 / 备注）。
3. 流量改成**一排 4 个水滴**：填充到第 N 个 = 第 N 档强度，点某个水滴即选中该档；
   右侧显示当前档位文字，选中后提供"取消"。
4. 保留：症状与心情的 chips、备注输入、清空这一天 / 保存。

## User Stories

1. 作为使用者，我想一眼看出"点数越多、流量越大"，而不是读四个词再比较。
2. 作为使用者，我希望弹层里的每一块都有明确的标签，而不是一片平铺的 chip。
3. 作为使用者，我想在日期标题上直接看到星期，不用自己算。
4. 作为使用者，我希望选错流量时能一键取消，而不是必须另选一个。

## Implementation Decisions

- `ui/common/Labels.kt`：新增 `LocalDate.fullDateWithWeekdayText()`（纯函数，
  `DayOfWeek.value` 是 1=周一..7=周日，映射到"周一..周日"）。**这是本轮唯一可自动验证的逻辑**
  （星期算错是很典型的 off-by-one），因此配单元测试。
- `ui/calendar/DayRecordSheet.kt`：
  - 新增私有 `RecordRow(label) { content }`，统一四个区块的层级；
  - 新增私有 `FlowDropletPicker`：`FlowIntensity.entries` 逐个渲染 `Icons.Filled.WaterDrop`，
    `flow.ordinal` 之内的水滴填充主色、之外淡化；每个水滴带 `contentDescription = 该档文字`（可访问性）；
  - 头部改用 `fullDateWithWeekdayText()`。
- **明确不改的两件事（含理由）**：
  1. **不把弹层改成日历下方的内联面板**。参考设计是内联的，但那会把交互从"显式保存"变成
     "每次点选立即写库"，还牵动"选中日必须在网格里有高亮"这一整套状态。
     这是一个产品决策（要不要即时保存），不该由我在无法核对真机的情况下顺手定掉。
     **留作下一轮的候选，需要使用者明确选择。**
  2. **不在网格上高亮选中的那一天**。格子当前已经有：易孕底色、胶囊条、排卵点、症状点、
     今天加粗——再加一种标记在看不到真机的情况下很难保证不糊成一团。

## Testing Decisions

**接缝**：`fullDateWithWeekdayText()`（纯函数，JVM 单测，CI 运行）。

**本轮流程**：先把该函数写成"只有日期、没有星期"（即当前行为），运行**确认测试红**，再补上星期。

边界：周六 / 周日 / 周一三个位置各一例（周末边界最容易错），外加跨年的一天。

**明确不测**：水滴选择器的交互与视觉（无设备，与既有决定一致）。

## Out of Scope

- 内联记录面板与"即时保存"（需产品决策，见上）。
- 网格内选中日高亮。
- 「经期结束」显式开关（要改 Room schema，走 Grill）。
- 症状/心情改成非 chip 的控件（10 个症状用 checkbox 或图标只会更糟）。
