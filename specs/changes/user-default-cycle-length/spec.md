# 用户填写的缺省周期长度（兜底预测）

Status: done

## Problem Statement

一位新用户在最终看到任何预测之前，必须先记录满 **3 次经期开始**（产生 2 个有效周期长度，才够 MEDIUM）。
在那之前，预测卡只有一句"还不能给出预计，再记录 N 次经期开始"。

但这位用户其实**知道自己大概是多少**——"我一般 35 天左右""我每次大概 6 天"。
这类信息只有用户自己知道，而现状是：不记录满 3 次，应用就一个字都不说。
用户带来一个"什么都看不到"的日历，很可能就此不再打开。

## Solution

在设置里让用户**主动填写**两个值：周期长度、经期长度。

- 填了之后，只要已有**至少一段经期**作为起点，就能立刻给出"下次经期预计"，并明确标注依据是用户自己填的。
- 一旦攒到 ≥1 个有效周期长度（即至少 2 段经期），**自动改用实际数据**，用户填的值退居幕后。
- 用户填的值只在预测里兜底，**永不进入统计量**（"平均周期长度"仍然是实测统计，样本不足就该显示"—"）。

这不是"给应用编一个默认 28 天"：编造的值来自应用，而这个值来自用户。

## User Stories

1. 作为刚装好应用的用户，我只记录过一次经期，但我在设置里填了"周期长度 35 天"，我希望立刻看到"下次经期预计 X 月 X 日"。
2. 作为使用者，我希望应用明确告诉我这个预计是**基于我填写的值**，而不是装作是从我的记录里算出来的。
3. 作为使用者，我希望在我记录到足够次数后，应用**自动改用我的实际数据**，不用我再去手动关闭什么。
4. 作为使用者，如果我填的值明显不合理（比如周期长度 12 天或 90 天），我希望应用指出并拒绝使用，而不是照着一个可疑的数字推算。
5. 作为使用者，我希望统计页的"平均周期长度"永远是我的**实测**结果，不会因为我填了缺省值就变成一个假数字。
6. 作为使用者，即使我填了缺省值，我也理解**排卵日与易孕窗口仍然不显示**——因为它们比"下次经期"更依赖我的实际数据。

## Implementation Decisions

### 口径（将同步到 `specs/capabilities/cycle-prediction.md`）

- **优先级**：有效样本 ≥1 → 用样本均值（`RECORDS`）；否则若用户填写且**通过范围校验** → 用它（`USER_DEFAULT`）；都不满足 → 不预测（`NONE`）。
- **范围校验与有效样本区间完全一致**，避免出现"应用拒绝用实测的 12 天，却允许用户手填 12 天"这种荒谬：
  - 周期长度 ∈ `[15, 60]`（= `MIN/MAX_VALID_CYCLE_LENGTH`）
  - 经期长度 ∈ `[3, 10]`（= `MIN/MAX_PERIOD_LENGTH_DAYS`）
  - 越界视为"未填写"（不是夹取成合法值——夹取会假装用户填的是别的东西）
- **置信度**：`USER_DEFAULT` 一律为 `LOW`。因此按既有规则**不显示排卵日、易孕窗口与阶段**。
  与参考设计不同（那个应用看起来会显示），这是刻意的：用户填的是"周期长度"，不是"排卵日"。
- **锚点**：仍必须有 ≥1 段经期作为起点。**一个零记录的新用户填了缺省值也仍然看不到预测**——没有起点可推。
  文案必须诚实，不能承诺"填了就一定看得到"。
- **不影响统计量**：`CycleStats.averageCycleLength / medianCycleLength / recentCycleLengths` 只由实测样本产生。
- **不变量**：`basis == NONE` 时所有日期字段为 `null`（与既有 `confidence == NONE` 的方向一致）。

### 代码

- `domain/model/CycleModels.kt`：新增 `enum PredictionBasis { NONE, USER_DEFAULT, RECORDS }`、
  `data class CycleDefaults(cycleLengthDays: Int?, periodLengthDays: Int?)`（`null` = 未填写，
  **不预置 28**——预置会制造"默认即事实"的错觉），以及 `CyclePrediction.basis` 字段。
- `CyclePredictor.analyze(periodDays, today, defaults = CycleDefaults.none)`：用**默认参数**扩展签名，
  既有调用点与既有测试无需改动。
- `data/prefs/SettingsStore.kt`：两个可空 Int 键（`default_cycle_length` / `default_period_length`）+ 一个 Flow + setter。
- `ui/settings/`：新增"缺省周期长度"卡片（两行，值为 `null` 时显示"未填写"），点击打开数字输入对话框，
  越界时禁用确认按钮并给出提示。
- `ui/calendar/`：`CalendarViewModel` 构造参数增加 `SettingsStore`，把缺省值传进 `analyze`；
  预测卡在 `basis == USER_DEFAULT` 时增加一行来源说明（"基于你填写的缺省周期长度 35 天，记录满 3 次经期后会改用你的实际数据"）。
- `ui/stats/`：`StatsViewModel` 同样传入缺省值（统计量本身不受影响，但阶段/位置与日历保持一致）。

## Testing Decisions

**接缝**：`CyclePredictor.analyze`（纯函数，JVM 单测，CI 运行）。新增测试类
`CyclePredictorUserDefaultsTest`，与既有 `CyclePredictorTest` 分开，避免后者变成大杂烩。

**本轮流程**：先把 API 与测试写出来，运行**确认它红**（桩实现故意忽略缺省值），再补实现转绿。

必须覆盖的边界（每条一个用例）：

1. 只有一段经期 + 用户填 35 天 → `basis == USER_DEFAULT`、`confidence == LOW`、下次经期 = 该段起始日 + 35
2. 有 ≥2 个有效样本 + 用户也填了值 → `basis == RECORDS`，用户填的值被忽略（实测优先）
3. 没有任何经期记录 + 填了缺省值 → 仍然不预测（无锚点）
4. 缺省周期长度越界（12 与 90）→ 视为未填写 → 不预测
5. 缺省值只填周期长度、不填经期长度 → 预测经期天数用缺省 5 天
6. 缺省值下 `cycleDay` 仍有值（事实），`phase == UNKNOWN`（推算被门槛挡住）
7. `USER_DEFAULT` 下 `ovulationDay` 与 `fertileWindow` 均为 `null`
8. 统计量不受缺省值影响（`averageCycleLength` 在无样本时为 `null`）

**明确不测**：设置页对话框的交互细节（无设备、无 UI 测试框架，与既有决定一致）。

## Out of Scope

- **首次引导里主动问用户这两个值**：本轮只在设置里提供入口。引导流程需要单独的 UX 决策（要不要拦在首启、能不能跳过）。
- 根据缺省值生成提醒通知（提醒本身还没做）。
- 备孕/避孕相关的任何用法（见 `PRODUCT.md` §3 反例表）。
- 让用户填"上次经期开始日"来覆盖零记录的情况：那等于新增一条记录，属于记录能力而非设置。

## Further Notes

- 与 ADR-0003 的关系需要写清楚：ADR-0003 拒绝的是"**应用自己编**一个默认 28 天"，
  本特性引入的是"**用户主动填写**的值"。两者的区别就是"谁在断言这件事"。
  这一点单独落 `docs/adr/0005`，并回标 ADR-0003 被其扩展。
- 诚实的局限：对**零记录**的新用户，本特性毫无帮助（没有锚点）。真正解决那一档需要"上次经期开始日"输入，
  已列入 Out of Scope。
