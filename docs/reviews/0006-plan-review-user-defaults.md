# 计划对抗审查：用户填写的缺省周期长度

独立性：**同源自审（不可得独立评审）**
轮次上限：5（本轮为 Round 1）
审查对象：`specs/changes/user-default-cycle-length/spec.md`

---

## Round 1

### 高

1. **它与 ADR-0003 表面冲突，若不说清"谁在断言"，后人会把这条当违规改回来。**
   证据：ADR-0003 "Decision 2" 原文拒绝"无有效样本时回退到默认 28 天"；
   本特性看起来正是在做同一件事。
   → 采纳：把区别写成一条不可省略的判据——**ADR-0003 拒绝的是"应用自己编"，
   本特性引入的是"用户主动填写"**。落 `docs/adr/0005`，并回标 ADR-0003 被其扩展。

2. **范围校验若与"有效样本区间"不一致，会产生自相矛盾的行为。**
   证据：既有口径里，实测得到的 12 天周期会被 `[15, 60]` 过滤掉、"不参与预计"；
   如果用户手填 12 天却被采用，等于"应用拒绝承认测量结果，却承认同一数字的口头声明"。
   → 采纳：缺省值走**同一区间**（周期 `[15,60]`、经期 `[3,10]`），
   且越界是"**视为未填写**"而不是夹取到边界。

3. **缺省值绝不能进入统计量。**
   证据：`CycleStats.averageCycleLength` 现在是"最近 6 个有效样本的均值"，统计页会把它当作测量结果展示。
   若把用户填的 45 天混进去，界面就会出现一个**看起来是测量值、实际是用户自述**的数字——这是伪造数据。
   → 采纳：口径里写死"统计量只由实测样本产生"，并加一条测试用例（用例 8）固定该行为。

### 中

4. **零记录的新用户填了值仍然什么也看不到。**
   证据：`nextPeriodStart` 的推导需要一个起点（最后一段经期起始日），零记录时不存在。
   → 采纳：spec 的 Problem Statement 不承诺解决那一档；口径里写明"仍需 ≥1 段经期作为锚点"；
   并在 Further Notes 里明确"真正解决零记录需要输入上次经期开始日，属记录能力，不在本轮"。

5. **兜底状态下不显示排卵日/易孕窗口，界面会比参考设计"少一块"。**
   证据：参考设计在用户只填了"周期长度 45 天"时也画排卵期；我们按 `confidence ≥ MEDIUM` 的门槛会留空。
   → 采纳：保留门槛（用户填的是周期长度，不是排卵日），但**必须由 UI 文案解释**，
   否则会被读成功能坏了。写进 ADR-0005 Decision 4 与 spec 的 User Story 6。

6. **用户误填会直接产生错误的预计，且这正是本特性的主要风险。**
   证据：用户填 45 天而实际 28 天 → 前两次预计会晚半个月。
   → 采纳：不假装能消除。缓解措施是"显式标注来源 + ≥1 个有效样本后自动切换"，
   并把它写成 ADR-0005 的代价 1。

### 低

7. **`null` 与"预置 28"的区别需要写下来。**
   证据：预置会让用户以为"这个数字是应用测出来的"。
   → 采纳：`CycleDefaults` 用可空字段（`null` = 未填写），UI 只把 28 当输入框 placeholder。

8. **扩展 `analyze` 签名会冲击既有 40+ 测试的编译。**
   → 采纳：用默认参数 `defaults: CycleDefaults = CycleDefaults.none`，既有调用点与测试零改动。

VERDICT: **REVISE**（8 条全部采纳，已落回 spec / ADR-0005，并在 ADR-0003 回标扩展关系）
