# ADR 0004：周期阶段与排卵信息的呈现口径

Status: accepted
Date: 2026-10-10

## Context

ADR-0003 决定了"怎么算"（最近 6 个有效样本的均值 + 置信度分档 + 黄体期 14 天假设）。它没有决定"怎么说"。
结果是核心能力只兑现了三分之二：记录月经 ✅、推测下次经期 ✅、**中间的排卵期实际不可见** ❌
（日历上只有一片"易孕窗口"底色，用户看不出排卵日，也不知道自己现在处在哪个阶段）。

同类应用普遍把周期画成阶段色带并标出排卵期。但这里有两个真实的取舍：

1. **两个区间的冲突**：既有的"易孕窗口"是 7 天（排卵日 −5 .. +1，基于精子存活时间的群体假设）；
   常说的"排卵期"约 3 天。两者都位于周期中间，天数不同、含义不同，同时展示会让人不知道该信哪个。
2. **没有医学背书**：本应用不是医疗设备。"排卵期""易孕"这类词天然带有避孕/备孕暗示。
3. **能力边界**：阶段是推算（依赖排卵日，门槛 ≥MEDIUM），而"今天是本次周期第几天"是事实（只要有记录）。

## Decision

1. **四段阶段模型**：`MENSTRUATION / FOLLICULAR / OVULATION / LUTEAL`，外加 `UNKNOWN`（数据不足）。
   划分依据是"今天相对于本周期预计排卵日的位置"，全部由既有 episodes 与 prediction 推导，不新增数据源。
   - 今天 ≤ 最后一段经期结束日 → `MENSTRUATION`（**实测**，不是推算）
   - 今天 < 排卵日 − 1 → `FOLLICULAR`
   - 排卵日 − 1 ≤ 今天 ≤ 排卵日 + 1 → `OVULATION`
   - 今天 > 排卵日 + 1 → `LUTEAL`
   - 无排卵日（置信度 < MEDIUM）或今天距记录太远 → `UNKNOWN`
2. **排卵信息以"单日"呈现，不以区间呈现**：预测卡写"排卵日预计 X 月 X 日"，
   **不写**"排卵期 X–Y"。这样界面上只存在一个区间（易孕窗口）和一个点（排卵日），不会互相打架。
3. **门槛沿用既有规则**：排卵日与阶段需要 `confidence ≥ MEDIUM`；易孕窗口同理（既有）。
   不一致的地方只有一个，且是刻意的：**"周期第 N 天"是事实，只要有经期记录就显示，不受置信度影响**。
4. **禁止评价性表述**：不得出现"已推迟 N 天""周期异常""是否排卵""安全期""是否怀孕"。
   周期第 N 天超过基准长度时照实显示，不加任何评价。
5. **本轮不改日历视觉**：日历已有四种视觉元素（实测经期 / 预计经期 / 易孕窗口 / 症状点），
   在无法于真机核对对比度与拥挤度之前，不新增第五种。阶段信息走文字，视觉改动留给能在设备上确认的那一轮。

## Consequences

**收益**：核心能力的第三块（中间的排卵期）第一次真正可见；阶段口径与预测口径写在同一处；
推理仍是纯函数，可在 JVM 上固定"今天"逐条测试；不新增任何权限、依赖或数据输入。

**代价（诚实记录）**：

1. **新用户看不到阶段**。记录满 ≥2 个有效周期长度（即至少 3 次经期开始）之前，阶段与排卵日都不存在，
   界面上只有一个"周期第 N 天"。缓解是 UI 明确给出进度说明，但**初次使用的体验仍然偏空**。
2. **依赖"黄体期固定 14 天"这个群体假设**，个体可能不成立。文案必须保持"预计"，且不得用于避孕/备孕。
3. **周期第 N 天可能是很大的数**（长期未记录时）。这是事实而非评价，但界面上仍可能让人不适；
   本轮接受，若将来收到相关反馈再单独处理。
4. **日历依旧没有明显的"排卵期"视觉**。用户可能仍觉得"看不到排卵期"——这是本轮刻意延后的取舍，
   不是遗漏；延后的理由是"无法在真机上验证视觉"，而不是"不重要"。
5. **为将来做通知埋了一个隐式约束**：若以后做提醒，通知内容是否包含"今天是排卵日"会直接牵涉锁屏可见性，
   属于隐私决策（需要新的 ADR），不能顺手决定。

## 准入三门槛自检

- 难回滚？**是** —— 它决定了用户如何解读自己的数据（"我现在是黄体期"），改口径等于改语义。
- 无上下文会困惑？**是** —— 后来者一定会问"为什么只显示排卵日不显示排卵期""为什么阶段要 MEDIUM 而周期天数不要"。
- 真实取舍？**是** —— 展示 3 天区间 vs 单日、是否新增日历标记、事实与推算门槛是否统一，都是真实的分歧点。
