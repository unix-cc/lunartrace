# ADR 0003：用统计均值法做周期预测，并显式输出置信度

Status: accepted
Date: 2026-10-10

## Context

预测"下次经期"至少三种做法：

| 方案 | 说明 | 问题 |
|---|---|---|
| A. 固定 28 天 | 全部用户套同一个值 | 对周期 32 天的人系统性错误，且会给出虚假的确定感 |
| B. 统计法：最近 N 次周期长度的均值，配合置信度分档 | 实现简单、可解释、可单元测试 | 不捕捉个体生理事件（疾病、产后、用药）造成的变化 |
| C. 机器学习 / 复杂模型 | 理论上更准 | 单人项目：无数据训练、无可解释性、无法验证、过度设计 |

同时存在一个产品级风险：**预测越"自信"，用户越可能把它当医学结论**。而本应用没有任何医学背书。

## Decision

1. 采用 **B：最近 6 个有效周期长度的算术平均** 作为预测基准长度（口径详见 `PRODUCT` 之外的业务口径表，落在 `specs/capabilities/cycle-prediction.md`）。
2. 有效样本限定为长度 ∈ `[15, 60]` 天；区间外样本**不参与预计**，但把个数单独展示（`excludedCount`），不删原始数据。
3. 显式输出**置信度分档** `NONE / LOW / MEDIUM / HIGH`，由"有效样本数 + 周期极差"决定：
   - 有效样本 0 → `NONE`，**不展示任何预测**
   - 1，或 ≥2 且极差 > 7 天 → `LOW`
   - 2–3 且极差 ≤ 7 → `MEDIUM`
   - ≥4 且极差 ≤ 4 → `HIGH`
4. **易孕窗口仅在置信度 ≥ MEDIUM 时展示**（排卵日 = 下次经期起点 − 14，窗口 = 排卵日 −5 .. +1）。
5. **不输出任何医学结论**：不问"是否怀孕"、不判"周期是否异常"、不建议就医。异常样本只提示"未参与预计"。
6. 预测是**纯函数**（`domain/prediction`），"今天是哪天"由 `core/time/Today.kt` 注入，因此可以在 JVM 单元测试里固定任意日期复现。该模块是本仓库**唯一**设硬覆盖率门禁（≥85%）的地方。

## Consequences

**收益**：可解释（用户能看懂"因为你的周期平均 31 天"）；可测试（纯函数 + 固定日期）；无外部依赖；不会给出虚假的强结论。

**代价（诚实记录）**：

1. **准不准取决于数据量**：新用户前 2 个月基本得不到有用预测（`NONE`/`LOW`），体验上"看起来没什么用"。这是刻意的：宁可不显示，也不误导。
2. **均值会被历史异常拖累**：一次 45 天周期会在未来 6 个周期内持续影响结果。用极差调低置信度可部分缓解，但不能消除。
3. **易孕窗口没有避孕价值**。窗口基于"黄体期固定 14 天"的群体假设，对个体可能不成立。**文案不得暗示可用于避孕/备孕决策**（已写入 `PRODUCT.md` §3 反例）。
4. **算法口径一旦改动，历史数据的解读随之改变**：同一份记录在改版前后可能显示不同预测。因此改口径触发 Grill 路径（`docs/agents/workflow.md` §3）。
5. **`excludedCount` 的解释成本**：用户会问"N 个样本被排除了，是不是我身体有问题"。文案层必须用中性措辞并明确"这不是医学判断"。

## 准入三门槛自检

- 难回滚？**是** —— 预测口径影响所有历史数据的解读，改变是用户可见的语义变更。
- 无上下文会困惑？**是** —— 后来者会问"为什么只有 6 个样本、为什么用均值而不是中位/加权、为什么要分置信度"。
- 真实取舍？**是** —— A/B/C 三方案真实存在，为"可解释 + 可测试 + 不误导"选择了 B。
