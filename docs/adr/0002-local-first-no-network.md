# ADR 0002：本地优先、零网络、不建设服务端

Status: accepted
Date: 2026-10-10

## Context

月经与症状记录属于高度敏感的健康数据。同类产品的主流做法是账号 + 云端同步，代价是：

- 必须申请 `INTERNET`，数据离开设备
- 必须承担账号体系、鉴权、服务端运维、数据泄露责任
- 单人项目无法维持服务端的安全水位（备份、审计、应急响应）

本项目为单人开发。备选方案：

| 方案 | 成本 | 风险 |
|---|---|---|
| A. 本地 SQLite + 无网络权限 | 低 | 换设备丢数据（用户可通过系统级迁移工具自行处理） |
| B. 本地 + 可选云同步（自建服务端） | 高 | 单人无法保障服务端安全；一旦泄露是健康数据 |
| C. 本地 + 第三方 BaaS 同步 | 中 | 把敏感数据托管给第三方，隐私承诺变质 |

## Decision

1. **Android 清单不声明任何联网权限**（无 `INTERNET`、无 `ACCESS_NETWORK_STATE`）。这条是产品的技术底座，不是"暂时没做"。
2. 数据只存本机：Room（结构化记录）+ DataStore（锁与设置元数据）。
3. **不做账号体系**、不做云端同步、不做跨设备迁移、不接入任何分析/崩溃上报 SDK。
4. `android:allowBackup="false"`：连系统自动云备份也关掉，避免健康数据经由 Google 云离开设备。
5. 数据主权由"一键清除（真删除）"承接，而不是由"导出到云"承接。
6. 该决定由 L1 门禁强制：`scripts/check-privacy-guards.py` 检查清单权限与备份开关，违反即提交失败。

## Consequences

**收益**：攻击面近乎为零（无网络栈可用）；隐私承诺可被用户用手机设置直接验证；无需服务端成本；离线永远可用。

**代价（诚实记录）**：

1. **换机丢数据**。用户自行用系统迁移/备份工具处理，应用不提供云恢复。这是明确接受的取舍。
2. **无法做账号级功能**：换机同步、多设备协作、分享给医生，全部永久放弃。
3. **清除数据不可逆**：误触即永久丢失。缓解是二次确认 + 文案明示"不可恢复"，**不提供回收站**（回收站需要在清除后保留数据，与"真删除"冲突）。
4. **未来若要加同步，是推翻性改动**：数据模型、UI（账号入口）、构建（网络权限）都要动，且触发 Grill 路径。写下此条以免后人以为它是小改。
5. 用户可能期待"自动备份"，产品文案必须提前说明（已写入 `PRODUCT.md` §3 反例）。

## 准入三门槛自检

- 难回滚？**是** —— 加回同步等于推翻数据存储与隐私承诺的根基。
- 无上下文会困惑？**是** —— 后来者会问"为什么不加同步，明明很简单"。
- 真实取舍？**是** —— A/B/C 三方案真实存在，且是为"单人无法保障服务端安全"这一具体理由选择了 A。
